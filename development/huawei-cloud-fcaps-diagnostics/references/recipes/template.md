# Recipe 轻量编写模板

维护者按[收录规则](STRUCTURE.md)复制到场景目录，沿用 .sop.md 命名。本模板供编写使用；主、子 recipe 都采用简短 KCS Overview 与 Guidance。可参考已迁移的 [SSH 超时草稿](login/ssh-timeout.sop.md)；具体章节按判断目标组织。

```markdown
---
id: 唯一且稳定的场景标识
intent: diagnose
environment: 适用资源与系统
status: draft
---

# 具体症状或任务名称

## Overview

- **Issue：**什么现象或任务适用，关键报错与必要排除条件。
- **Environment：**适用环境和必要前提；已有信息复用，缺少且影响当前判断时再补。
- **Resolution：**交付什么结果；具体指导见下文。诊断边界与恢复目标分别说明。
- **Cause：**可选，仅写已有依据的可复用原因及确认条件；没有合适内容则删除此项。

## Guidance

### 明确一个判断目标

说明当前要区分什么，以及需要哪些事实。引用适用的命令契约或子 recipe；分别说明不同结果支持什么判断、还不能证明什么，以及继续、跳转或结束的条件。

[待补 DOC-01：支持本判断的内部产品语义与适用边界；无缺口则删除]

### 根据证据选择下一步

按剩余疑问选择检查，复用已取得的事实。涉及特定工具或通道时，确认其输入、输出含义、权限和执行影响；未绑定的工具能力保留为缺口。

[待补 TOOL-01：内部工具的准确入口、输入输出与失败语义；无缺口则删除]

### 交付或返回上层

说明何时已足以回答、需要转诊或因关键依赖受阻而结束；记录已有结论、证据缺口与下一步。子 recipe 返回调用方；恢复是否成功以原问题的复测记录为准。

[待补 CASE-01：工单中改变判断的证据、实际处理和验证结果；无缺口则删除]
```

## 填写与拆分

- Overview 每项保持简短；Cause 可选。Guidance 的标题、数量和分支按实际场景调整，上述三节只是写作示意，不是固定执行顺序。
- 每个判断写清“要区分什么、需要什么证据、结果怎样改变下一步”；必要约束和退出条件贴近相关判断，不强制独立的 Constraints/Stop conditions 栏目。共同规则引用既有共享文档。
- 工具实现与判断思路分开：具体命令只在 commands 定义；缺少内部工具时标明所需事实。通用工具也保留系统、权限和采集范围；友商工具只提供候选，不靠改名适配。
- 拆分按[最小单元规则](STRUCTURE.md#最小单元与拆分)选择篇内分支、并列或条件子 recipe；主、子篇共用本模板。

## 待补项

在缺口影响判断或调用的位置写 `[待补 ID：所需内容]`。DOC 指产品/帮助文档，TOOL 指工具契约，CASE 指工单证据；编号在对应补充记录范围内唯一。有补充清单时链接到具体项。

维护记录说明去哪找、补什么、补回哪个段落及当前状态；来源版本、适用范围和运行验证分别记录。研究摘录与真实验证保留在开发/QA 资料中。影响适用性或执行条件的缺口未补齐时，只交付已有证据和缺口，继续不依赖该条件的工作。

填写完成后删除模板说明和无关占位；保留真实缺口及 draft 状态。reviewed 只表示内容审阅，真实环境实测另记。
