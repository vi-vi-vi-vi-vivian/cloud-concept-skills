# 搜索 CLI 内网自测计划

目标：判断搜索 CLI 是否让 CodeAgent 更快找到适用资料、减少无关读取，并保持回答质量。结论分为“脚本可运行”“检索有效”“Agent 整体提效”三层，前一层通过不能代替后一层。

本计划可直接交给内网 CodeAgent。真实工单、回答、日志与结果保存在内网仓库外；仅计划和合成模板随代码转移。

## 1. 运行检查

完整复制仓库，保留隐藏的 .abstract.md、.overview.md 文件，使用 Python 3.10+。脚本仅用标准库，无需模型 SDK、搜索服务或 OpenKB。没有 rtk 时直接执行下列命令。

在仓库根目录运行：

~~~bash
python3 --version
python3 -m unittest discover -s skills/drafts/huawei-cloud-fcaps-diagnostics/tests -v
python3 skills/drafts/huawei-cloud-fcaps-diagnostics/scripts/search.py search '官方文档' --kind directory
python3 skills/drafts/huawei-cloud-fcaps-diagnostics/scripts/search.py show 'directory:documents'
python3 skills/drafts/huawei-cloud-fcaps-diagnostics/scripts/search.py search '磁盘映射' --kind document --product ecs
python3 skills/drafts/huawei-cloud-fcaps-diagnostics/scripts/search.py search '磁盘' --kind command --environment linux
python3 skills/drafts/huawei-cloud-fcaps-diagnostics/scripts/search.py show 'command:LINUX/block-devices'
python3 skills/drafts/huawei-cloud-fcaps-diagnostics/scripts/search.py search 'yum源' --kind document --arch arm64
~~~

验收：12 项测试通过；正常输出可解析 JSON；精确命令返回原契约；目录 show 返回 L1。最后一项允许零命中，但须声明覆盖和官方入口。换一个工作目录，用脚本绝对路径执行 show，应同样成功。

当前快照：4 个目录导航、2 份指南、31 个官方链接、1,362 个命令契约、9 篇 recipe。数量未来可变；记录实测数量和文件散列，不固定这些数为永久门禁。没有 catalog 依赖。工具说明正文、Helper、OpenKB 和官方正文不在搜索索引中，须按导航另读。

## 2. 两个 agent 的分工

| 角色 | 可见信息 | 职责与产物 |
| --- | --- | --- |
| 执行 agent | 当前工单公开输入、指定资料与获准证据 | 独立选资料并作答；产出 answer.md、引用及未解决事项，平台保留工具轨迹 |
| 观察 agent | 实验配置、工具事件；执行结束后才读 gold | 被动记录、事后评分，产出 observation.json 与证据位置 |
| 人工复核者 | 原工单、参考标准、匿名答案与轨迹 | 确认标准，处理关键错误与评审分歧 |

观察 agent 不提示查询词、ID 或答案，不代查资料，不要求执行者补看某处；建议只能用于下一版。观察者的检索、token、耗时单独记录，不计入执行者成本。

使用运行平台导出的真实工具输入输出、时间及 usage。不能从简述猜测已经读取正文，更不需要记录内部思考。不能实时观察时，先导出轨迹，观察 agent 再事后评审即可。

执行者不能读取 gold、其他轮答案或观察报告。优先用独立工作区/文件权限隔离；仅靠提示词时记录“未强隔离”，检查越界读取，越界轮作废。

## 3. 需要准备什么

真实工单＋历史回答只是起点，还需要当时可见的信息、可接受的依据与人工复核标准。历史回答可能过时或漏项，不能当唯一标准答案。

| 材料 | 要求 | 内容 |
| --- | --- | --- |
| 初始工单 | 必需 | 原问题、初始附件、用户口语和原始错误描述 |
| 现场证据 | 排障题必需 | 日志、报错、配置、OS/架构/区域/版本、脱敏拓扑、时间线；区分初始已知和后续发现 |
| 历史回答与结案结果 | 有则提供 | 处理步骤、真实根因、恢复验证；未闭环不能标为已解决 |
| 人工复核 gold | 必需 | 必答点、必要追问、可接受的不同路径、错误结论、操作边界、来源及适用日期 |
| 检索相关性标注 | 检索评测必需 | 有用的命令 ID、recipe、目录/指南、官方 URL；区分导航和可支持判断的 L2 |
| 固定资料与工具返回 | 必需 | 相同技能、知识库、官方正文镜像、现场查询返回；记日期和 SHA-256 |
| 固定交互回复表 | 多轮题必需 | 常见追问的确定回复；未知统一回复未知，两组一致 |
| 分组标签 | 必需 | 产品、OS、架构、FCAPS、复杂度、信息充分性、覆盖类型 |
| 边界与干扰题 | 必需 | 相近 SKU、不同架构/OS、同症不同根因、过期来源、导航相关但正文不适用 |

后续才发现的根因放 gold，不能提前混入初始输入。脱敏须保留对象间关系，用一致占位符，避免改变题目可解性。

先用 5 条开发题跑通并修改配置，再冻结至少 20 条独立评测题，每题 A/B 各重复 3 次，共 120 个执行轮。资源有限先做 10 题 × 两组 × 1 次，只用于找明显问题。

20 题建议按主要目的分层：

- 8 条：现有命令、recipe 或官方链接能直接帮助。
- 4 条：组合多份依据，例如容量、分区、文件系统与挂载。
- 4 条：本地缺覆盖，应转官方来源、既有 OpenKB 入口或专家。
- 4 条：信息不足、相近型号/架构误导、历史知识冲突，正确行为可能是补证或保留未知。

各层兼顾 Linux/Windows、云侧/主机侧、ARM、网络/存储/权限/费用。之前 20 个问题可以作为选题线索，不能仅凭一句问题证明根因。截断的“多次感染勒……”须补全或标为信息不足。

按事件/客户/根因家族拆分开发集与评测集，同一事件的消息、改写、重复工单留在一组。若用工单生成 OpenKB，评测题及其派生知识须从知识库排除；独立历史案例可作为双方一致的资料。

## 4. 内网数据布局与模板

以下是实验约定，非搜索脚本参数；当前仓库没有自动启动双 agent 的运行器，内网 CodeAgent 按计划组织。

~~~text
<内网评测目录>/
  manifest.json
  visible/T001/
    ticket.md
    context.json
    evidence/
    followups.json
  gold/T001.json
  snapshots/
    skill/
    official-docs/
    openkb/                 # 可选，两组一致
  runs/T001/<匿名组别>/repeat-01/
    answer.md
    trace.jsonl
    metrics.json
  review/T001/<匿名组别>/repeat-01/observation.json
  report.md
~~~

manifest 记录数据集版本、commit 与未提交差异散列、资料散列、模型实际标识/版本、采样参数、上下文/输出预算、工具版本、网络模式、超时、随机种子和时间。凭据留在平台，仅记录配置是否可用。

单条 gold 的合成模板，由内网人工填写，执行者不可见：

~~~json
{
  "case_id": "T001",
  "status": "needs_evidence",
  "coverage": "local_direct",
  "required_points": ["区分云盘容量、分区、文件系统与挂载点"],
  "required_questions": ["确认目标磁盘与文件系统类型"],
  "acceptable_sources": [
    {"type": "command", "id": "command:LINUX/block-devices", "relevance": 2}
  ],
  "mandatory_evidence_groups": [
    {"description": "块设备与挂载拓扑", "any_of": ["command:LINUX/block-devices"]}
  ],
  "forbidden_claims": ["未确认设备就提供可直接执行的格式化操作"],
  "historical_answer": "另存于内网；此处为合成例子",
  "reviewed_by": "内网专家",
  "review_date": "实际复核日期"
}
~~~

relevance：0 无关；1 有助导航/部分相关；2 适用且可支持判断。可人工追加有依据的等价路径，记录理由，不因措辞不同判错。

## 5. A/B 配置与运行顺序

A：现有 L0/L1 导航＋rg/文件读取。本轮不调用搜索 CLI，也不读 search.md 或脚本/测试。

B：相同资料＋CLI。未知条目先 search，选中后 show，已知 ID 可直接 show。CLI 未覆盖时按导航读取工具说明、Helper、OpenKB、官方正文；允许必要 rg/文件读取，但记录回退原因和次数。

同模型、预算、环境、资料、网络、工单信息。A 的启动说明只替换 SKILL 中 CLI 优先入口段；B 保留，其他内容一致，保存两份提示及差异。不要将旧 459 条 catalog 与新版 31 条链接对比，否则混入资料变化。

先跑离线回放：固定证据、技能、同一官方正文镜像，现场命令用录制返回替代，不真实执行排障或变更。缺镜像标来源受阻，两组一致。追问由固定回复表回答，不能由观察者即兴发挥。

然后选少量题做联网/内网只读工具测试，单独报告；两组来源与目标一致。网络、权限受阻和资料无覆盖分开计，不冒充召回失败。不为评测接入或改动生产资源。

每个工单/重复轮生成成对任务，按固定种子安排 A→B 或 B→A。每轮全新执行者上下文，禁用跨轮记忆，不共享生成缓存、输出或日志；只读资料可共享。不能让一个持续会话先看 A 答案再做 B。

协议违规轮保留并单列，修复配置后可重跑，不能只删差结果。服务临时失败也单列，按统一策略最多补跑一次。观察者按匿名编号评分，但工具轨迹会暴露 CLI 使用，因此这是匿名评审，不能声称盲评。若需要盲评，由人工另读去组别的最终答案和证据包，独立评质量；工具过程分仍由观察者负责。

## 6. 可交给 CodeAgent 的提示词

### 调度提示

> 阅读本计划，先运行脚本检查，再核对测试集、gold 隔离和快照。缺材料就列待补项，不虚构真实答案。齐备后按 manifest 创建 A/B 成对任务，每轮启动全新执行 agent；观察 agent 被动记录、事后评分。只改变资料发现入口，保存真实工具轨迹和结果。没有现场执行授权时只用录制证据。所有真实材料与结果留在指定内网目录，最终按本计划给出报告与限制。

### 执行 agent 共用提示

> 回答指定 visible 工单，按本轮技能入口收集必要依据，输出结论、适用条件、引用、未知与下一步。可请求 followups，由运行器返回固定回复。本轮是回放评测，命令仅提出并匹配录制结果，不真实执行现场命令。只读 visible、指定快照及本轮工具返回，不读 gold、其他轮答案或观察报告。依据充分即结束；预算不足保留已有证据和未知。输出 answer.md，工具事件由平台记录。

A 补充：

> 资料发现使用 L0/L1、rg 和文件读取；本轮不调用搜索 CLI，不读搜索说明或实现。

B 补充：

> 未知条目优先 search→show，已知 ID 可直接 show。按已有分面过滤，不猜未知值。缺覆盖或入口不适用时按技能回退并说明原因。L0/L1 用于选读，结论须读取适用原文；拿到官方链接不等于核对了正文。

### 观察 agent 提示

> 被动观察，不指导、代查或改答案。依据真实工具事件记录查询、候选、读取量、时间与失败。执行结束后再读 gold 和匿名答案，按量表评分并引用轨迹位置。接受有依据的等价路径，历史回答不是唯一标准。无法确定标 uncertain，不编数字。区分覆盖不足、召回失败、选错结果、未读正文、推理错误和环境阻塞。先逐项提交评分，再汇总 A/B；轨迹会暴露组别，不声称盲评，关键错误交人工复核。

## 7. 指标和评分

先做固定查询检索小测，再做 Agent A/B，两个结论分开。

检索小测：每题 1～3 个固定查询和必要过滤，由人工确认相关性。

- Hit@5：本地有可接受条目的查询中，前 5 是否含 relevance=2；仅导航命中另计。
- Precision@5：前 5 中 relevance=2 的数量/实际返回数量，零返回记 0。
- MRR：首个 relevance=2 排名倒数，未命中记 0。
- 必要证据覆盖率：最终读取满足的 mandatory_evidence_groups/全部必要组，每组接受任一等价依据。
- 无覆盖题单列，评能否说明边界、转正确入口，不混入有答案题的召回分母。status=ok 的弱匹配不是有效命中。
- ARM 未标注不等于 x86，过严过滤应观察能否放宽；不把零命中当无能力。

端到端每轮记录：

| 指标 | 口径 |
| --- | --- |
| 首次有效 L2 依据时间 | 收到工单到实际读取适用契约/原文；L0/L1 或仅 URL 不算；没取得记未达到，不填 0 |
| 总完成耗时 | 同一起止，分开模型/工具耗时，排除排队与观察者事后评分；超时单列 |
| 工具调用数 | 全部调用、资料发现/读取调用分别计；CLI 自身调用也计 |
| 返回量 | 执行者实际收到的工具输出 UTF-8 字节，重复读重复计，截断按收到部分计 |
| token/费用 | 有真实 usage 才填输入/输出/缓存及费用；没有填 null，用字节作代理，不能叫 token |
| 阅读效率 | 重复、无关、整卷读取、CLI 回退的次数，附判定证据 |
| 最终质量 | 以下量表与通过率；不用长短或文风评分 |
| 异常 | 超时、服务失败、越界、协议违规、外部受阻分别记 |

质量四项，每项 0/1/2，共 8 分：事实与适用条件；诊断/补证路径；证据与引用；处置建议与验证。0 实质错误/缺失，1 部分达到，2 充分。≥6 且无关键错误算通过；信息不足题正确补证、保留未知可以满分。

关键错误：捏造观测、无依据宣称根因或恢复、近似 SKU/错误架构替代、与证据冲突的危险操作。关键错误须人工确认，不能只看模型评分。

## 8. 汇总与试点判断线

每题先对重复轮取中位数，再计算该题 B 相对 A 的变化。质量同时报告通过轮数和通过题数；一题 3 轮中至少 2 轮通过才算该题通过，任一轮关键错误均单独进入人工复核，不能被多数票掩盖。报告成对差值中位数、改善/持平/退步题数、质量通过数与关键错误。按覆盖层和复杂度分组，不只报总平均。超时、未取得有效依据单列，不悄悄删掉。

试点建议在跑前冻结：

- B 通过题数不少于 A，不新增人工确认的关键错误。
- 配对资料返回量或首次有效依据时间，中位数改善至少 20%。
- 另一项成本中位数不恶化超过 10%，列退步题原因。
- 无覆盖题诚实说明边界，不把来源不可用写成已核对或已解决。

这些是项目试点标准，不是通用行业阈值；20 题不能证明所有工单都提效。人工复核全部关键错误、分歧、uncertain，再抽查双方均通过的题。

报告包含版本和样本组成、A/B 配置差异、运行有效性、检索指标、配对成本与质量、胜/败案例、阻塞、下一步。分别判断可运行、本地检索表现、Agent 提效；不足写待验证。

## 9. 本机复查（2026-11-09）

发现并修正国际站链接产品被识别为 intl 的问题，现在从产品栏目识别 elb。Markdown 单元格解析保留普通路径反斜杠，继续支持转义管道。增加全量来源定位、国际站分面、异地工作目录和输入边界测试。

Python 3.10.1 下 12 项测试通过，9 个 CLI 冒烟用例通过（含其他工作目录调用），仓库公共检查通过。连续启动 20 次“磁盘＋Linux 命令”搜索，中位数 71.1 ms，范围 68.9～72.7 ms，包含进程启动与索引构建；这不是与 rg 的对比。

本机结果不能代替内网模型、真实工单和其他 OS 验证；A/B 尚未执行，没有宣称提效。
